## 这一版改了什么

### 在线更新：从「能查能下」变成一条能走完的路

上一版只有「拿到最新版本号 → 下载 exe → 静默安装」三步，中间几个坑都留在代码里没出口。这一版逐个补上：

- **只认稳定版**：草稿、`prerelease`、以及 tag 带 `-rc`/`-beta` 后缀的发行版一律跳过。把 RC 当正式版推给所有人，等于一次批量降级。
- **条件请求省额度**：检查时带 `If-None-Match`，ETag 缓存在 `<userData>/updates/release-cache.json`，GitHub 对 304 不计入限流。撞上匿名 60 次/小时的额度时，按响应头算出「约 N 分钟后再试」，不再笼统报一句「更新源不可读」。
- **检查与下载用不同超时**：检查是 25 秒总超时；下载不设总超时，只保留连接与读超时（reqwest 的 timeout 覆盖整个响应体，7 MB 的包在慢网下必然被打断）。断流保留 `.part` 并用 `Range` 续传，最多 3 次，界面会显示「正在重连第 N 次」而不是进度条无故掉回 0。
- **可取消下载**：新增「取消」，流式读到下一块就停、删掉 `.part`，按「已取消」通知界面。
- **装完自动重启**：NSIS 的 `/SILENT` 不会执行「安装完运行应用」，所以拉起安装器时同时挂一个隐藏的 `powershell` 观察者，等安装器退出再启动新版本；本进程随即退出，让出 exe 与 dll。此前装完不重启，用户以为没装上。
- **代理**：设置 → 刷新、并发与更新 → 更新代理，只接受 `http://`/`https://`，写入口就校验；留空表示直连，并沿用系统的 `HTTPS_PROXY`。
- **错误分诊**：后台把限流、源不可读、网络失败、数据异常分别成句，不再靠匹配响应里的 `403`/`404` 猜原因（那样会把限流误报成「仓库已被删除」）。

### 界面

- **静默检查**：启动 8 秒后检查一次，之后每 6 小时一次；发现新版本只在顶栏「设置」按钮上点一个点，菜单第一条顶出「发现新版本 vX」，不弹窗打断。可在配置中心关掉。
- **发行说明按 Markdown 渲染**：`marked` + `DOMPurify`，仓库正文按不可信输入处理；外层固定高度可滚动，长说明不会把「下载」按钮顶出可视区。
- 检查结果收敛到一处 store，顶栏提示点与更新弹窗共用同一份，不会两边各查一次；手动点「检查更新」仍然强制走网络，不复用缓存结果。
