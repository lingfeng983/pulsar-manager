## 这一版改了什么

三个问题都是在真实 broker（Pulsar 3.3.9 standalone）上装包复现出来的，不是纸面推演。

### 关闭窗口后不再自己弹回来

「关闭」是把窗口收进托盘，但有两处会把它重新显示：

1. 启动兜底：本意是「页面加载失败时别让用户对着托盘图标猜窗口去哪了」，判断条件却写成了「当前不可见」。启动 3 秒内点叉，窗口就会被它弹回来。改成「从没显示过」才补显示。
2. 页面重载：WebView2 在内存紧张时会丢弃并重载页面，重载会再触发一次加载完成事件。用户已经把窗口收进托盘，几分钟后它自己出现在屏幕上。现在收进托盘期间的重载不再显示窗口。

托盘「显示主窗口」与二次启动唤回是用户主动要看，仍然照常恢复。

### Reader 读得多时条数不再卡在 500

消息列表只保留最近 500 条，而 Reader 的「限量」可以开到 10000。原先界面显示的是列表长度，读到 500 条之后数字就不再变——看起来像读取停了，其实还在进。现在列表内容与累计条数分开：裁剪只作用于列表，累计数按去重后的新增条数累加（重投不重复计数），超出上限时显示「已读 N 条（界面保留最近 M 条）」。

### Reader 的起始位置现在真的按起点走

逐个验证五种起始位置，修掉三处与界面承诺不符的地方：

- **最近 N 条 / 指定时间 / 按 ID 定位扫完不结束。** 底层 Reader 是非持久 consumer，扫到末尾不会给出「流结束」信号，只会一直等新消息。而这三个起点没有尾部锚点，只能从最早扫过去——扫完就再也等不到事件。其中「最近 N 条」又恰恰要等扫描结束才把结果发出来，界面上就是「一直在读、一条都不显示」，只能手动停。现在连续 1.5 秒没有新消息就判定已追上末尾并收尾。
- **按 ID 定位会把后面的消息一起带出来。** 命中之后没有停，继续读到打满限量，与「找到就显这一条」的提示矛盾。现在命中即停。
- **扫不到起点时的措辞。** 原先只有「按 ID」会被判成失败，「指定时间」会以「完成 + 0 条」收尾，看起来像「这个时间点之后确实没消息」。现在两种起点都明确报错，并按起点给不同的话：时间点更可能是落在未来，ID 更可能是已过期或不属于该 topic。

「最早」与「最新之后」不加这条判定——它们是真正的游标，选了「最新之后」就是要持续收新消息，提前收工反而是错的。

界面提示里写「最多扫 2 万条 / 15 秒」，实际护栏是 20 万条 / 30 秒，这次一并对齐。

## 工程化

- 新增的最小 CI 里，Rust job 曾在编译期失败：Tauri 的 `generate_context!` 会校验前端产物目录存在，而 CI 只 checkout 不构建前端。现在在跑单元测试前放一个占位文件，前端产物本身由另一个 job 负责。

## 验证

- 五种起始位置在真实 broker 上逐条对照 Message ID：最早 10 条、最近 10 条、指定时间 20 条、按 ID 1 条、最新之后 5 条，全部符合预期。
- 边界：空 topic 的「最近 N 条」给提示并收尾；1000 条上取最近 500 / 取 5000 都正确；不存在的 Message ID 与未来时间点都返回明确错误；「最早」限量 1000 读满 1000 条。
- 关窗后 1 秒、4 秒、10 秒三次检查窗口都没有回来；再次启动只唤回同一窗口，进程数仍为 1。
- Reader 限量 1200 读取后界面显示「已读 1200 条（界面保留最近 500 条）」。
- `npm run typecheck`、`npm run lint`、`npm run format:check`、`npm run build:renderer` 全部通过。
- `npm run selftest`（模板引擎 35 项）、`npm run selftest:docs`（文档中心 25 项）全部通过。
