## 一、系统架构设计

本工具采用**Electron \+ React 前后端分离混合架构**，兼顾桌面端原生交互体验、跨平台一致性与复杂数据处理能力，分层解耦、职责清晰，支持高扩展性与可维护性。整体分为四层架构，各层级职责如下：

### 1\.1 表现层（UI Layer）

基于 Electron \+ React \+ TypeScript 构建跨平台可视化界面，核心负责用户交互响应、页面渲染、ECharts 监控图表展示、前端状态管理、用户操作交互反馈等能力，保障三端统一的轻量化交互体验。

### 1\.2 桥接层（IPC Bridge）

依托 Electron 原生 IPC 进程间通信机制，搭建渲染进程与主进程的数据交互通道。通过 Zod 实现通信参数类型校验，解决跨进程传参异常、类型不统一问题，实现前后端无缝、安全的数据通信。

### 1\.3 核心服务层（Core Service）

部署于 Electron 主进程或独立 Sidecar 进程，是系统核心业务能力载体。统一封装 Pulsar Admin REST API、Pulsar Client SDK、Prometheus 时序数据拉取、SSH 隧道代理、消息编解码、压测引擎等核心能力，提供标准化业务服务。

### 1\.4 持久层（Storage Layer）

采用嵌入式 SQLite 数据库，存储用户集群配置、连接凭证、个性化配置、历史操作日志、压测模板等数据。所有敏感数据通过 AES\-256 加密存储，实现数据安全隔离与本地持久化，无需依赖第三方服务。

## 二、核心模块详细设计

### 2\.1 多集群与安全管理模块

本模块支持多套 Pulsar 集群统一管理，提供全场景安全连接与内网穿透能力，适配开发、测试、生产、私有化多环境。

- **配置加密机制**：集群连接地址、JWT Token、mTLS 证书路径、密钥等所有敏感信息，写入 SQLite 前统一通过 AES\-256\-GCM 加密处理，杜绝明文存储，保障凭证安全。

- **SSH 隧道代理**：内置基于 ssh2 库的轻量化隧道管理器，纯 JS 实现无系统依赖。支持用户一键开启 SSH Proxy 模式，自动分配本地随机端口，映射远端 Pulsar 8080（管理端口）、6650（消息端口），实现内网集群安全穿透访问，同时支持密钥认证、跳板机多级代理、网络波动自动重连。

### 2\.2 资源管理引擎（Resource Engine）

统一管控 Pulsar 租户、命名空间、Topic、订阅等核心资源，通过接口抽象\+缓存策略，大幅提升资源加载与页面响应速度，规避高频请求导致的集群压力。

- **API 抽象层**：定义统一的 IPulsarAdminClient 标准接口，完全屏蔽底层 HTTP 请求细节。内置请求队列、自动重试、限流熔断机制，统一管控所有 Pulsar Admin 请求，防止高频刷新造成 Broker 过载。

- **LRU 缓存策略**：针对租户、命名空间、Topic 树状资源结构，启用 LRU 内存缓存。用户切换页面节点时，优先加载本地缓存实现秒级渲染，同时后台静默发起 API 校验更新数据，兼顾交互流畅度与数据准确性。

### 2\.3 消息调试与浏览器（Message Explorer）

提供全功能消息查看、解码、调试、批量压测能力，支撑开发、测试、问题排查全场景消息运维需求，杜绝大消息、高频数据阻塞 UI。

- **多维度游标定位**：深度对接 Pulsar Client Reader API，支持通过时间戳、唯一 MessageID、起始位（Earliest）、最新位（Latest）四种方式精准定位消息，动态创建 Reader 实例拉取目标消息。

- **Web Worker 异步解码管线**：将消息解码、Schema 解析等 CPU 密集型操作下沉至 Web Worker，完全不阻塞主线程。自动适配 JSON、Protobuf、Avro 等官方 Schema 解析规则，解析失败时自动降级为 HEX/Base64 原始格式展示，兼容所有消息格式。

- **生产者池批量压测引擎**：采用预创建生产者池模式，支持多实例并行发送消息。支持自定义 Payload 模板导入、多速率压测配置，通过事件总线实时向前端推送 TPS、消息延迟、成功率等核心指标，实现可视化压测。

### 2\.4 监控与可视化模块（Metrics Dashboard）

对接 Prometheus 时序监控体系，实现 Pulsar 集群指标可视化、数据降噪、异常告警，全方位监控集群运行状态。

- **轻量化 Prometheus 适配器**：内置标准 PromQL 客户端，预置 Pulsar 官方核心监控语句，涵盖消息入队速率、出队速率、订阅积压、Broker 负载、分区流量等核心指标。

- **时序数据降采样处理**：针对桌面端内存限制，对原始监控数据进行降采样降噪。7 天以上历史数据自动聚合为分钟级、小时级粒度，在保证趋势准确性的前提下，大幅降低内存与渲染压力。

- **系统级告警推送**：支持对接 Alertmanager Webhook，捕获集群异常指标后，在桌面端右下角弹出系统原生通知，实现离线弹窗告警，及时感知集群故障。

## 三、核心数据流转链路

以**查看 Topic 消费积压（Backlog）**核心场景为例，标准化数据流转链路如下：

1. 用户在前端 UI 选中目标 Topic，触发 `fetchTopicStats` 数据请求动作；

2. 前端渲染进程通过标准化 IPC 通道，向 Electron 主进程发送数据查询指令；

3. 主进程接收指令后优先校验本地缓存，命中则直接返回缓存数据，未命中则主动调用 Pulsar Admin 接口：`GET /admin/v2/persistent/{tenant}/{namespace}/{topic}/stats`；

4. 解析接口 JSON 响应数据，提取订阅组下`msgBacklog` 积压核心字段，封装为统一标准 DTO 对象；

5. 主进程通过 IPC 将标准化数据回传给前端，驱动仪表盘、数字动画、趋势图完成页面渲染展示。

## 四、异常处理与安全规范

### 4\.1 网络异常容错机制

- **超时管控**：统一配置全量网络请求超时阈值，Admin API 默认 5s、消息读取默认 10s、监控查询默认 8s，超时自动终止请求并抛出友好提示。

- **熔断降级**：针对频繁失败的集群请求、监控请求，触发自动熔断机制，短期内停止重复请求，避免无效请求占用资源、拖垮应用性能。

### 4\.2 内存防泄漏规范

- 消息浏览器强制限制单页最大展示 500 条数据，滚动加载时自动销毁不可见 DOM 节点与 JS 对象引用；

- 组件销毁时自动解绑所有 IPC 监听器、定时器、事件总线订阅，杜绝内存堆积泄漏。

### 4\.3 高危操作合规管控

针对重置游标、清理订阅积压、删除 Topic、批量修改权限等破坏性高危操作，强制启用二次确认机制，要求用户手动输入目标 Topic 名称校验，同时完整记录审计日志，留存操作人、操作时间、操作参数，满足运维合规要求。

- **依赖最小化**：仅引入业务必需依赖，杜绝冗余大体积工具库，优先使用原生 API 实现基础能力；

- **版本精确锁定**：所有依赖锁定固定版本，禁止使用模糊范围版本，规避版本自动升级引发的兼容性问题；

- **安全常态化审计**：每迭代执行 `npm audit` 修复高危漏洞，严禁引入存在已知安全风险的依赖包；

- **打包优化**：所有依赖支持 ESM 模块化，打包开启 Tree Shaking，剔除无效代码，压缩安装包体积。

### 6\.2 自动更新机制

- **增量差分更新**：基于 electron\-updater 实现差分更新，更新包体积控制在 10MB 内，相比全量更新节省 80% 以上流量；

- **分层更新策略**：小版本后台静默下载、重启自动安装；大版本弹窗提示，支持立即更新或延后处理；支持灰度比例推送新版本；

- **故障自动回滚**：版本更新失败时，自动回退至上一稳定版本，保障应用可用性不中断。

### 6\.3 应用安全加固

- **官方代码签名**：三端安装包统一数字签名，Windows 完成微软 SmartScreen 认证，macOS 完成官方公证，规避系统拦截告警；

- **进程沙箱隔离**：渲染进程开启沙箱模式，禁用原生 Node\.js 能力，仅通过 IPC 白名单与主进程通信，防止恶意代码注入；

- **权限最小化**：仅申请网络、文件读写、系统通知必要权限，禁止获取管理员/root 高危权限；

- **敏感信息清零**：内存中临时存储的 Token、密钥使用完毕立即清空，禁止明文输出至日志文件。

## 七、性能优化专项设计

### 7\.1 启动速度优化

- **代码分包懒加载**：主进程拆分核心启动代码（控制在 500KB 内）优先加载，监控、压测等非核心功能动态懒加载；前端按路由分包，首屏仅加载核心集群管理模块；

- **并行冷启动预热**：启动阶段并行执行数据库初始化、配置解密、集群探活、缓存加载；首屏优先渲染骨架屏，异步加载业务数据，保障首屏渲染时间 \<2s；

- **V8 缓存加速**：启用 Electron V8 代码缓存，二次启动速度提升 50%，大幅优化日常打开体验。

### 7\.2 内存占用优化

- **大数据虚拟滚动**：资源列表、消息列表启用虚拟滚动，仅渲染可视区域数据，支持 10w\+ 级 Topic 无卡顿展示；消息浏览器严格控制内存占用，稳定峰值 \<500MB；

- **精细化缓存淘汰**：限制资源缓存、时序数据缓存最大容量；应用后台静置 5 分钟后，自动清理非活跃缓存，主动释放内存；

- **长效泄漏防护**：全局监听定时器、事件订阅、IPC 监听，组件销毁强制解绑；定时执行内存快照检测，异常泄漏自动记录日志。

### 7\.3 交互响应优化

- **乐观更新机制**：用户新增、修改、配置变更操作，优先更新本地 UI 与缓存，后台异步提交接口，失败自动回滚并弹窗提示；

- **重复请求合并**：短时间内重复 API 请求自动合并，快速切换资源时取消冗余请求，避免请求堆积、页面抖动；

- **CPU 任务离线处理**：消息解码、Schema 解析、数据降采样、文件导入导出等密集型任务全部下沉 Web Worker，彻底解放 UI 主线程，保证界面丝滑不卡顿。

## 八、可扩展性与开放能力设计

### 8\.1 插件化架构

基于进程隔离实现轻量化插件生态，支持第三方功能扩展，不侵入核心源码，保证系统稳定性与可扩展性。

- **插件沙箱隔离**：插件独立进程运行，无法直接访问主进程敏感 API，杜绝安全风险；

- **标准化扩展点**：开放自定义菜单、自定义标签页、自定义消息解码器、自定义监控面板等扩展能力；

- **通用开放 API**：封装 Pulsar 资源管理、消息读写、配置操作等标准化 API，供插件调用；

- **插件市场能力**：内置插件商店，支持一键安装、卸载、更新插件，支持本地私有插件导入；

- **官方示例插件**：提供消息脱敏、数据批量导出、资源拓扑可视化等官方插件，支撑通用扩展场景。

### 8\.2 自定义脚本引擎

- **消息自定义处理**：支持用户编写 JS 脚本实现消息过滤、格式转换、自定义告警规则，适配个性化调试需求；

- **安全脚本沙箱**：脚本运行于隔离 VM 环境，禁止访问本地文件、网络资源，仅开放消息上下文专属 API，杜绝恶意脚本风险；

- **通用脚本模板**：内置 JSON 格式化、Base64 解码、Protobuf 反序列化等常用模板，支持一键复用。

### 8\.3 个性化主题与布局

- **多主题适配**：内置浅色、深色、护眼三套官方主题，支持用户自定义主色、字体、间距，主题配置可导入导出；

- **自由布局调整**：支持拖拽调整面板位置、隐藏冗余模块，个性化布局自动持久化保存。

## 九、用户体验（UX）专项设计

### 9\.1 离线模式能力

- **离线可用范围**：已缓存的集群配置、资源树、历史日志、已加载消息支持离线查看、检索；

- **离线操作队列**：断网状态下的资源修改、配置变更操作暂存本地队列，网络恢复后自动批量同步，同步失败提供手动处理入口；

- **实时状态提示**：全局常驻网络状态图标，离线状态醒目提示，避免用户无效操作。

### 9\.2 全局快捷键系统

- **默认全局快捷键**：Ctrl/Cmd\+K 全局搜索、Ctrl/Cmd\+T 新建标签、Ctrl/Cmd\+W 关闭标签、Ctrl/Cmd\+Z 撤销、F5 刷新页面；

- **自定义配置**：支持用户修改、禁用快捷键，规避与本地其他软件冲突。

### 9\.3 批量高效操作能力

- **批量运维**：支持多选 Topic 批量授权、批量清理积压、批量删除；支持集群、Topic 配置批量导入导出；

- **快捷操作入口**：资源右键快捷菜单、全局命令面板，快速调用全量功能；

- **操作回溯**：支持最近 20 步操作撤销/重做，高危操作撤销二次校验，防止误操作。

### 9\.4 国际化多语言

内置中文、英文、日文三套语言包，支持一键无缝切换；语言包独立配置，支持用户自定义扩展翻译内容，适配国际化使用场景。

## 十一、运维诊断与可观测性设计

### 11\.1 分级日志系统

- **日志分级**：分为 DEBUG/INFO/WARN/ERROR 四级，默认仅记录 INFO 及以上级别日志，兼顾调试能力与日志体积；

- **自动轮转**：单日志文件上限 10MB，自动分割归档，最大保留 7 天日志，避免磁盘占用过高；

- **自动脱敏**：日志自动屏蔽 Token、密钥、敏感消息内容，杜绝敏感信息泄露；

- **一键诊断导出**：支持打包导出系统信息、应用配置、7 天内全量日志，快速支撑问题排查。

### 11\.2 崩溃与异常上报

- 集成 Sentry 异常监控，自动捕获主进程、渲染进程崩溃、未捕获 JS 异常、API 请求异常；

- 异常上报附带应用版本、系统信息、用户操作上下文，精准定位问题；

- 完全匿名上报，仅收集故障数据，不获取用户隐私，支持用户自主开关。

### 11\.3 性能埋点与诊断

- 核心指标全埋点：启动耗时、API 响应时长、消息加载耗时、内存占用、页面渲染耗时；

- 内置性能诊断看板，用户可自主查看应用性能数据，识别卡顿、慢请求问题；

- 自动监控慢操作，API 响应超 3s、UI 卡顿超 100ms 自动记录日志，用于迭代优化。

## 十二、兼容性与多环境适配设计

### 12\.1 Pulsar 多版本兼容适配

- **API 适配层**：统一封装多版本 API 差异，自动识别集群版本，将 2\.x/3\.x 字段、接口差异统一转换为标准 DTO，屏蔽版本差异；

- **特性智能降级**：低版本不支持的事务、分层存储等功能自动隐藏，同时文字提示用户版本适配范围；

- **集群版本检测**：连接集群时自动探测 Pulsar 版本，展示当前集群支持的全部功能清单。

### 12\.2 全场景认证兼容

全面适配 Pulsar 官方所有认证模式：无认证、JWT Token、mTLS 双向认证、OAuth2、Athenz、Kerberos，完美适配开发、私有化、企业级大数据环境、云服务环境。

### 12\.3 多部署环境适配

- 自建集群：支持直连、SSH 隧道穿透访问内网集群；

- K8s 集群：集成 kubectl，支持自动端口转发访问容器内 Pulsar 服务；

- 云服务集群：适配 StreamNative Cloud、阿里云、腾讯云 Pulsar 专属认证与访问规则；

- 私有化部署：支持自定义 CA 证书、内网代理配置，适配企业私有化隔离环境。

## 十三、核心模块补充细节设计

### 13\.1 Schema 管理模块

- 全类型支持：兼容 JSON、Protobuf、Avro、String、Int 等所有 Pulsar 原生 Schema 类型；

- 可视化解析：自动解析 Schema 结构，树形展示字段、数据类型、注释信息；

- 版本管控：支持查看 Schema 历史版本、版本对比、一键回滚；

- 消息校验：发送消息前自动匹配 Schema 规则，非法消息直接拦截并提示错误原因。

### 13\.2 事务与高级消息能力

- 事务消息：支持事务状态查询、手动提交、事务回滚，可视化展示事务执行记录；

- 延迟消息：支持自定义延迟时间发送消息，可视化查看延迟队列堆积数据；

- 顺序消息：识别顺序 Topic，标识消息排序键，保障顺序消息调试可视化；

- 死信队列：自动识别死信 Topic，支持死信消息重发、批量导出、一键清理。

### 13\.3 权限管理模块

- 权限可视化：树形展示租户、命名空间、Topic 全层级权限配置，支持按用户、角色筛选；

- 批量授权：支持批量配置权限、复用权限模板，提升运维效率；

- 权限审计：完整记录所有权限变更操作，支持历史记录查询与溯源。

### 13\.4 压测引擎增强能力

- **多压测模式**：固定 TPS 阶梯升压、最大吞吐压测、自定义速率曲线压测，适配不同性能测试场景；

- **自动化压测报告**：测试结束自动生成报告，包含 TPS 趋势、延迟分布、消息成功率、系统资源占用；

- **模板化复用**：支持保存、导入压测配置模板，实现一键复现压测场景。

## 十四、数据一致性与状态同步设计

### 14\.1 多窗口状态同步

基于 Zustand \+ IPC 实现多窗口状态实时同步，集群配置、资源数据、操作状态全局统一。高危操作执行时全局锁定，杜绝多窗口重复操作导致的数据异常。

### 14\.2 分层缓存失效策略

- **主动失效**：用户新增、修改、删除资源后，立即清空对应模块缓存，保证数据实时一致；

- **被动 TTL 失效**：资源树缓存 5 分钟、Topic 统计数据 30 秒、监控数据 10 秒，自动更新；

- **后台静默刷新**：页面常驻时后台定时更新数据，无感知刷新 UI，无需手动刷新。

### 14\.3 配置变更生效机制

集群连接、主题、布局等所有配置修改后实时生效，无需重启应用。多端配置冲突时，以最后修改时间为准，自动提示用户配置变更并完成合并。
