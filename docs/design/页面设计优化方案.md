# Pulsar Manager 页面设计优化方案

> 审查范围：`src/renderer` 全部 20 个 `.tsx`（约 400KB）+ `docs/design/Pulsar 桌面管理工具 UI 详细设计规范（最终完整版）.md`
> 方法：静态代码审查 + 全量模式扫描（未启动应用做运行时验证，结论均为代码级可复现证据）

---

## 结论摘要

**设计系统"地基"是好的，"上层建筑"缺失。**

`index.css` 已经建立了一套完整的 CSS 变量设计系统（3 套主题、间距/圆角/字号/阴影全token 化），代码注释质量很高，请求竞态、快捷键作用域、CSP 构建断言等工程细节都处理得相当扎实。

问题在于：**这套设计系统没有被页面层消费。** 9 个页面各自手写布局，出现 4 种标题写法、6 种占位状态、4 套删除确认；280 处内联样式散落在 20 个文件里，而全局 CSS 只有 5KB。结果是规范文档写了什么、代码就各写各的。

最紧急的不是重构，而是 **1 个暗色主题下完全不可读的真 bug**。

| 维度 | 评价 | 关键依据 |
|---|---|---|
| 设计系统定义 | 🟢 良好 | 3 套主题 token 完整，色彩/间距/圆角/阴影齐备 |
| 设计系统落地 | 🔴 薄弱 | 280 处内联样式 vs 5KB 全局 CSS，token 覆盖率约 32% |
| 规范符合度 | 🟡 部分 | 4px 栅格、字号梯度、三态占位均有多处违反 |
| 页面一致性 | 🔴 较差 | 9 页面 4 种头部写法，无共享骨架组件 |
| 可访问性 | 🔴 缺失 | 全 renderer 0 处 `aria-label` / `role` / `tabIndex` |
| 工程实现质量 | 🟢 良好 | 注释密度高，竞态处理、作用域隔离到位 |

## 一、P0｜立即修复：暗色主题右键菜单完全不可读

**这是本次审查发现的唯一功能性缺陷，优先级最高。**

`TabWorkspace.tsx` 使用了 3 个 **从未在任何 CSS 中定义过的变量名**：

| 位置 | 代码 | 实际情况 |
|---|---|---|
| `TabWorkspace.tsx:253` | `var(--color-bg-container, #fff)` | 变量未定义 → 兜底为**白色** |
| `TabWorkspace.tsx:282` | `var(--color-error, #ff4d4f)` | 变量未定义 → 兜底为亮色红 |
| `TabWorkspace.tsx:290` | `var(--color-fill-secondary, #f5f5f5)` | 变量未定义 → 兜底为亮色灰 |

而 `index.css` 里定义的同义变量叫的是**另一个名字**：`--color-bg-elevated`（第 12 行）、`--color-danger`（第 8 行）。

**后果**：切到暗色主题后，页签右键菜单的背景是 `#fff` 白底，菜单项文字却取 `var(--color-text-primary)` = `#f5f5f7`（近白色）→ **白底白字，完全不可见**。护眼主题同理（浅底浅字）。

### 修复方案

```css
/* index.css —— 在 :root 与两套主题中补齐缺失变量 */
--color-bg-container: #ffffff;        /* 亮色 */
--color-fill-secondary: #f2f3f5;     /* 亮色 */
```

并在 `[data-theme='dark']` / `[data-theme='eyeCare']` 块内分别补上对应值（暗色建议 `--color-bg-container: #2e2e33`、`--color-fill-secondary: #232327`）。

**衍生防护**：当前 `var(--x, 兜底值)` 的写法把"变量拼错"伪装成了"降级显示"，是这次 bug 能潜伏至今的根因。建议后续**移除所有颜色类 var 的硬编码兜底值**——变量缺失就应该在开发期暴露，而不是静默渲染成亮色。

## 二、P1｜规范一致性：代码违反自家规范文档

规范文档不是"参考建议"，是本项目的验收标准。以下 3 类为**明确的规范违反**。

### 2.1 4px 栅格违规（12 处）

规范 §1.3.1：*"基础栅格：4px 最小单位，所有间距、内边距、圆角均为 4px 倍数"*

代码中出现 `20px`、`40px` 等非 4 倍数内边距：

```
Home.tsx:382          padding: '20px 0'
Home.tsx:398          padding: '40px 0'
MessageBrowser.tsx:812  padding: '40px 0'
TopicDetail.tsx:683/708  padding: '20px 0'
TopicDetail.tsx:718/756  padding: '40px 0'
TopicDetail.tsx:789      padding: '20px'
NamespaceDetail.tsx:166  padding: '20px'
NamespaceDetail.tsx:220  padding: '40px 0'
TenantDetail.tsx:147     padding: '20px'
TenantDetail.tsx:199     padding: '40px 0'
ResourceTree.tsx:798     padding: '40px 16px'
```

**注意**：这些集中在**空状态**上——同一个"空状态"在 `TopicDetail` 是 `20px`，在 `TenantDetail` 是 `40px`。间距差异肉眼可见，但完全是无意义的随机值。

### 2.2 字号梯度违规（9 处）

规范 §1.3.1 定义梯度：`12 / 14 / 16 / 18 / 20px`，实际使用：

| 字号 | 位置 | 问题 |
|---|---|---|
| `13px` | `MessageBrowser.tsx:575,580,589`、`TopNav.tsx:477,478` | 不在梯度内 |
| `24px` | `TopicDetail.tsx:636,646,656`、`Home.tsx:386` | 超出梯度上限 |
| `18px` | `HomeTopology.tsx:350` | 在梯度内，但与页面标题混用 |

页面标题当前有 **4 种写法**：

```
ConfigCenter.tsx:164     <Title level={4}>        + padding: 16（裸值）
PluginMarket.tsx:206     <Title level={4}>        + var(--spacing-lg)
Home.tsx:256             <h2 fontSize:'20px'>     + marginBottom: var(--spacing-lg)
MetricsDashboard.tsx:464 <h2 fontSize:20>        + marginBottom: var(--spacing-md)
```

后两者还混用了字符串 `'20px'` 与数字 `20`，下边距取了 `spacing-lg`(16) 和 `spacing-md`(12) 两个不同值。

### 2.3 三态占位状态未统一（规范 §2.3 明确要求）

规范 §2.3：*"全局统一加载、空数据、异常三类占位状态"*

实际情况是 **6 种写法**：

| 状态 | 写法 | 位置 |
|---|---|---|
| 空态 | antd `<Empty>` | `MessageBrowser:813`、`PluginMarket:284,288`、`MetricsDashboard:666,697,732,763` |
| 空态 | 自绘图标+文字 | `Home:397-403`、`HomeTopology:348-352`、`ResourceTree:802-806` |
| 空态 | 纯文字 | `TopicDetail:680-688/706-714/754-762`、`TenantDetail:196-204` |
| 加载 | 嵌套 `<Spin>` | `MetricsDashboard:534-535` |
| 加载 | 手写 200px 居中 Spin | `TenantDetail:92-95`、`NamespaceDetail:111-114` |
| 错误 | `<Alert>` / `message.error` / 独立 state | `Home:274-283` / `MetricsDashboard:493` / `TopicDetail:60` |

`ConfigCenter`、`ShortcutConfig`、`ClusterConfig` 三个页面**完全没有**空态/错误态。

## 三、P2｜架构缺失：建立共享骨架与原语

这是本方案的主体工作量，也是解决前两节问题的**根本手段**。

### 3.1 建立 `PageShell` + `PageHeader`（消除 4 种头部写法）

新增 `src/renderer/components/common/PageShell.tsx`：

```tsx
interface PageShellProps {
    title: React.ReactNode;
    subtitle?: React.ReactNode;
    actions?: React.ReactNode;   // 右侧操作区
    children: React.ReactNode;
}
```

统一契约（对齐规范 §1.3.1、§2.3）：
- 根容器：`padding: var(--spacing-lg)` + `height: 100%` + `overflow: auto`
- 标题：20px / fontWeight 600 / 下边距 `var(--spacing-sm)`
- 副标题：`--color-text-secondary` / 14px
- 操作区右对齐，支持换行

**收益**：9 个页面头部视觉基线一次性对齐，规范 §2.3 的"内容区统一内边距 16px"自动落地。

### 3.2 建立三态容器组件（消除 6 种占位写法）

新增 `components/common/StateBlock.tsx`，统一 `loading` / `error` / `empty` 三态：
- 统一使用 antd `Empty` / `Spin` / `Result`
- 空态内边距统一 `var(--spacing-xxl)`（32px），从根源上消除 2.1 的栅格违规
- 支持 `error` 时传入 `onRetry`

**收益**：`MetricsDashboard` 的 4 处逐字重复空态（`:666,697,732,763`）直接收敛为 1 处。

### 3.3 合并重复页面（消除 ~200 行重复）

`TenantDetail.tsx`(215 行) 与 `NamespaceDetail.tsx`(235 行) **结构高度同构，28 行非空代码完全相同**（空态 div、删除确认、加载态逐字重复）。

建议抽取共享的 `<ResourceListPage>`：以列定义 + 路径参数驱动，两个页面各传入自己的 `columns` 和加载逻辑。

### 3.4 统一危险操作确认（消除 4 套实现）

当前并存：`Modal.confirm`(`Home:153`、`TopicDetail:389`、`ResourceTree` 5 处)、受控 Modal(`TopicDetail:824`)、`Popconfirm`(`ConfigCenter:270,286`、`PluginMarket:316`、`ShortcutConfig:214`)。

危险样式也有两套：`okType:'danger'`(`ResourceTree`) vs `okButtonProps.danger`(`ConfigCenter`、`PluginMarket`)，且 `TopicDetail:824` 的受控 Modal **完全没有 danger 语义**。

统一为 `useConfirmDanger()` hook。顺带落实规范 §8：*"高危操作强制输入资源名校验"*。

### 3.5 内联样式治理（中期）

280 处内联样式的分层处理建议：

| 场景 | 处理方式 |
|---|---|
| 重复的卡片/面板容器 | 抽为 `<Panel>` 组件 |
| 重复的样式对象（如 `fieldLabel`） | 提为共享常量或 CSS 类 |
| 一次性布局微调 | 保留内联，不强行 CSS 化 |

Vite 原生支持 CSS Modules（无需新增依赖），复杂样式可逐步迁移为 `*.module.css`。**不建议一次性全量重写**——按页面迭代时顺手迁移即可。

## 四、P3｜可访问性与交互一致性

### 4.1 可访问名缺失（影响最广）

全 renderer **0 处** `aria-label` / `role` / `tabIndex`。纯图标按钮存在三种写法并存：

- 用 `title=`：`HomeTopology:362-363`、`ClusterTopology:405-407`
- 无任何提示：`MetricsDashboard:658-661,689-692,724-727,755-758`、`MessageBrowser:745-749`、`PluginMarket:324-331`
- 用 `<Tooltip>`：`TopNav` 工具区

**建议**：新建 `components/common/IconButton.tsx`，把 `title`/`aria-label` 设为必填 prop，从类型层面杜绝无障碍名缺失。

### 4.2 键盘可达性

- 右键菜单仅绑定 `onContextMenu`(`ResourceTree:400-401`、`TabWorkspace:42`)，**无键盘等价入口**——纯键盘用户无法操作
- `Home.tsx:261-267` 的 Switch 配裸 `<span>` 文本，无 label 关联

### 4.3 Tooltip 覆盖不足

规范 §4.5 要求"按钮悬浮提示实时刷新自定义按键"，当前 Tooltip 仅 28 处且集中在 7 个文件，工具栏按钮基本无悬停提示。

## 五、规范中"已定义但未实现"的能力

规范 §2.1 定义 TopNav 为**五大区域**，实际只实现了四个：

```
✅ Logo 区      TopNav.tsx:393-406
✅ 全局搜索     TopNav.tsx:409-430（320px、Ctrl+K 均符合规范）
❌ 状态区       网络状态 / 后台任务进度 / 更新提示 —— 整块缺失
✅ 工具区       TopNav.tsx:437-447
✅ 菜单区       TopNav.tsx:456-460
```

状态区缺失意味着后台压测任务的进度、连接状态异常都无处呈现——用户只能等弹窗。建议作为独立需求排期，不并入本次优化。

## 六、执行路线图

按**风险收益比**排序，前两阶段可独立交付：

### 阶段一：修 Bug（0.5 天，立即做）
1. `index.css` 三套主题补齐 `--color-bg-container` / `--color-fill-secondary` / `--color-error`
2. 全局检索并清理颜色类 `var()` 的硬编码兜底值，让变量缺失在开发期暴露
3. 三套主题各走查一遍右键菜单、`Home`、各详情页

**验收**：暗色主题下页签右键菜单文字清晰可读。

### 阶段二：统一页面骨架（3~5 天）
1. 落地 `PageShell` + `StateBlock` 两个共享组件
2. 先迁 `ConfigCenter`、`PluginMarket`（已有 antd Title，改造成本最低）→ 再迁 `Home`、`MetricsDashboard` → 最后迁详情页
3. 迁移时顺手修掉 2.1 的 `20px/40px` 栅格违规

**验收**：9 个页面头部视觉基线一致；`grep` 检查 `20px`/`40px` 内边距归零。

### 阶段三：消除重复（3~5 天）
1. 合并 `TenantDetail` / `NamespaceDetail` → `<ResourceListPage>`
2. 统一危险操作确认 → `useConfirmDanger()`
3. 补齐缺失页面的空态/错误态

**验收**：删除确认全局只剩一种实现；所有页面三态齐全。

### 阶段四：可访问性（2~3 天，可并行）
1. 引入 `IconButton` 强制可访问名
2. 右键菜单补键盘入口
3. 工具栏 Tooltip 补齐
