# 生产者 / 消费者工作台方案

> 本文是生产者工作台与消费者工作台的设计说明：数据面全部走原生 pulsar-client（admin REST 上没有 send/peek 路由），持久化落本地 SQLite，界面挂在两个独立顶级页签内，一个页签里可以并存多个会话。逐条实现顺序见「七、分批实施」。

## Context

用户要把 Pulsar 的基本使用方式集成进桌面端：创建生产者、编辑 JSON 报文（支持字段随机生成、从列表随机取一个、格式化），创建消费者监听队列数据并可选/可配置消费模式，以及其他值得集成的基础能力。

关键前提：**能力的地基已经存在，缺的是「工作台」这一层。** `src/renderer/pages/MessageBrowser.tsx` 已有 send/consume/read 三态面板，主进程 `src/main/services/pulsar-native-client.ts` 已封装原生客户端的 producer 单发、consumer 订阅循环、reader 扫描，并解决了 MessageId 跨 IPC、批量回推、会话互斥、退出清场等硬问题。所以这不是从零做起，而是：

- 把「一次性单发」升级为**常驻生产者会话 + 模板变量引擎 + 连续限速投递**；
- 把「整会话 autoAck 开关」升级为**逐条 ack / nack / 累计确认 / 游标回放 / 死信**；
- 补**模板与会话配置的持久化**、**peek 最近消息**、**发送历史**、**schema 校验**；
- UI 落到**独立顶级页签**，TopicDetail 里的轻量发送面板原样保留。

已确认的取舍（用户已选定，不再讨论）：独立 producer/consumer 页签；CodeMirror 6 做 JSON 编辑器；建 SQLite 表持久化模板与会话配置；扩展范围含手动 ack/nack+死信、持续批量发送、schema 校验、peek/重投/消息追踪。

三条必须守住的运行时红线（仓库记忆 + 代码注释已记录）：

1. **admin REST 上没有 send / peek / message-by-id / lastMessageId 路由**（返回 HTML 404）。数据面一律走原生客户端。
2. **`Reader.readNext(timeout)` 在超时真正到期时段错误**（pulsar-client 1.18.0，exit 139）。沿用 `hasNext()` 闸门 + 250ms 轮询（`pulsar-native-client.ts:141-143`、`:549-557`），新循环照抄。
3. **TLS + SSH 隧道组合被原生客户端硬拒**（`pulsar-native-client.ts:63-67`），UI 要显式说明而不是让它崩。

另：`applySchema()` 每次启动先执行基线 `SCHEMA_SQL` 再按 `user_version` 补迁移（`sqlite.ts:36-46`），基线全是 `IF NOT EXISTS`——**新增表只需把 DDL 加进基线并升 `SCHEMA_VERSION`，`migrate()` 不需要新分支**；只有加列才必须写迁移。

## 一、数据库

`src/main/database/schema.ts:5-80` 末尾追加三张表，`src/main/database/sqlite.ts:13` `SCHEMA_VERSION 4 → 5`（`migrate()` 加一行注释说明 v5 无数据修补，免得后来者以为漏写）。

```sql
CREATE TABLE IF NOT EXISTS message_templates (
    id TEXT PRIMARY KEY,
    cluster_id TEXT NOT NULL,
    topic_uri TEXT NOT NULL DEFAULT '',          -- '' = 通用模板，跨 topic 复用
    name TEXT NOT NULL,
    body TEXT NOT NULL,                          -- 未解析态，含 ${} 占位符
    variables_json TEXT NOT NULL DEFAULT '[]',
    properties_json TEXT NOT NULL DEFAULT '{}',
    producer_options_json TEXT NOT NULL DEFAULT '{}',
    schema_mode TEXT NOT NULL DEFAULT 'none',    -- none | inline | broker
    use_count INTEGER NOT NULL DEFAULT 0,
    last_used_at TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (cluster_id, topic_uri, name),
    FOREIGN KEY (cluster_id) REFERENCES clusters(id) ON DELETE CASCADE
);
CREATE TABLE IF NOT EXISTS consumer_session_configs (
    id TEXT PRIMARY KEY, cluster_id TEXT NOT NULL,
    topic_uri TEXT NOT NULL DEFAULT '', subscription TEXT NOT NULL DEFAULT '',
    name TEXT NOT NULL, config_json TEXT NOT NULL,
    use_count INTEGER NOT NULL DEFAULT 0, last_used_at TEXT,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL,
    UNIQUE (cluster_id, topic_uri, subscription, name),
    FOREIGN KEY (cluster_id) REFERENCES clusters(id) ON DELETE CASCADE
);
CREATE TABLE IF NOT EXISTS send_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cluster_id TEXT, topic_uri TEXT NOT NULL,
    template_id TEXT, template_name TEXT NOT NULL,
    body_preview TEXT NOT NULL,                  -- 只存正文前缀，不存解析后载荷
    body_bytes INTEGER NOT NULL, message_count INTEGER NOT NULL DEFAULT 1,
    message_id TEXT, status TEXT NOT NULL, error_message TEXT,
    created_at TEXT NOT NULL
);
```
配 `idx_message_templates_scope(cluster_id, topic_uri)`、`idx_consumer_configs_scope(…)`、`idx_send_history_scope(cluster_id, topic_uri)` + `idx_send_history_created_at`。

三个决定：
- `topic_uri` 用 **`''` 而非 NULL** 表示通用：SQLite 唯一索引里 NULL 互不相等，用 NULL 会导致同名模板无限堆积。
- 模板/会话配置 **CASCADE 删除**（离开集群就是死数据）；`send_history` 学 `operation_logs` 的 `SET NULL` + `template_name` 冗余存名（删模板不丢历史）。前提是 `sqlite.ts:81` 的 `foreign_keys = ON` 已开。
- **不做接收历史表**：单条正文上限 5MB，落库就是几十 GB。发送历史同理只存预览，并加 `cleanupSendHistory(maxRows = 2000)`（照 `cleanupOperationLogs` 写法，在 `initDatabase` 里紧挨 `cleanupOperationLogs()` 那行调用）。**不自动 VACUUM**，注释写明原因（WAL 下 DELETE 不缩文件，而定期 VACUUM 会卡主进程）。

DAO 追加到 `sqlite.ts` 的 SSH 域之后、用户设置之前，沿用扁平函数 + `*_ALLOWED_FIELDS` 白名单（照 `updateCluster:195-216`）风格：`listMessageTemplates(clusterId, topicUri?)`（传了就 `topic_uri IN (?, '')`）、`getMessageTemplateById`、`insert/update/deleteMessageTemplate`、`touchMessageTemplateUse`；consumer 配置同六件套；`insertSendHistory` / `listSendHistory(limit 默认 200)`。复制/重命名在 handler 层组合，DAO 不写 `copyXxx`。

## 二、原生客户端层（`pulsar-native-client.ts`）

- **`Session`（`:151-160`）加 `kind: 'consumer' | 'reader' | 'producer'` 和 `pending: PendingAcks | null`**，不建并行结构——这样 `stopSession:295`、`removeCluster:306`、`stopSessionById:568`、`runSession:442`、`index.ts` 的 will-quit 全部自动覆盖新的 producer 会话。加 `MAX_SESSIONS = 32` 内存护栏。
- **`reserveSession:370-387` 改成显式双模式** `mode: 'exclusive' | 'parallel'`：Exclusive 订阅保持现有互斥与报错文案（确实会互踢）；Shared/Failover/Key_Shared、reader、producer 走 `parallel`（键追加 `#${sessionId}`）。调用点只有 `:468` 和 `:526` 两处，`removeCluster` 按 clusterId 过滤不看键，不受影响。
- **持久生产者 `startProducer(...)` 进 `sessions`**：`client.createProducer(buildProducerConfig(options, topic))`，`session.close = flush → close`（顺序不能反，批量时最后一段还堆在原生队列，理由同 `load-test.ts:451-463`）；会话跑一个 `while (!stopped) await sleep(200)` 驻留循环以便 `runSession` 正常收尾。构造器从 `load-test.ts:188-200` 上提为共享的 `buildProducerConfig`。
- **连续发送** `startFlow(sessionId, …)` 复用 load-test 的四件现成资产：限速器 `:98-111`、在途窗口 SendWindow `:125-148`、reservoir 延迟统计 `:58-94`、容量类错误整体收手 `:469-477`。**提取到新文件 `src/main/services/native-flow-utils.ts`，load-test 改成 import**（共享而非复制）。统计按 500ms 节流推 `msg:producer-stats`，绝不逐条过 IPC。
- **手动 ack 协议**：Message 原生对象不过界。主进程 `PendingAcks` 以**单调 `seq`** 为键持有 `Message`（不用 messageId：批消息里多条的 `messageId.toString()` 可能相同，会串消息；seq 还天然表达到达顺序，正好支撑累计确认）。双阈值淘汰 `MAX_PENDING_ACKS=1000` 且 `MAX_PENDING_BYTES=64MB`，被淘汰条目标记「超出可确认窗口，将由 broker 重投」——**不写这条就是主进程内存增长 bug**。ack 前必须校验 `!session.stopped`（consumer 关闭后再 nack 是 use-after-free）。**`autoAck === false` 时必须开 `batchIndexAckEnabled: true`**，否则逐条 ack 不推进 markDeletePosition，界面显示已确认而积压不降。
- **载荷**：`shared/types.ts` 的 `Message` 加两个可选字段 `ackSeq?: number`、`messageIdBytes?: string`（`getMessageId().serialize()` 的 base64，供按 id 回放）。可选 → `MessageBrowser` 现有列不受影响。`toRendererMessage:121-133` 加第二参数。
- **批次字节闸门**：`pump` 的 flush 判定（`:403-409`）现在是 50 条/300ms，补「累计 base64 字节 ≥ 4MB 立即 flush」，否则 50×5MB 一次过界。
- **peek 最近 N 条** = 一次性非会话、走 `trackShortLived:204`：`createReader({startMessageId: earliest}) → seekTimestamp(now - windowMs) → 轮询收满 count / scanLimit / deadline`。**陷阱必须写进注释**：`hasNext()` 是同步且只看本地队列，新建 Reader 队列必空，首个 `!hasNext` 绝不能当结束条件，要「连续 N 次空轮询或墙钟到期」。`readNext()` 不带参数，整体套 `withHardTimeout`。
- **重发 vs 回放**要分开：重发 = 取该条 `data`+properties 再 `send` 一次；回放 = `consumer.seek(MessageId.deserialize(Buffer.from(messageIdBytes,'base64')))`，需要活着的 consumer，没有就退到 admin `resetcursor/{timestamp}`（记忆确认带时间戳可用、无参 500）。

## 四、变量 / 模板引擎（真正的新代码）

**支点决定：占位符只允许出现在 JSON 字符串值内部**，于是模板永远是合法 JSON —— CodeMirror 的 `json()` + `jsonParseLinter` 始终绿色、格式化始终可用，不存在「填了占位符就报语法错」的半成品状态。

**类型保持规则**：字符串值整体恰好是一个占位符 → 替换整个值（`"${int(1,50)}"` → 数字 `50`）；否则做字符串插值（`"SKU${int(100,999)}"` → `"SKU421"`）。这一条同时拿到「合法 JSON」和「能生成数字/布尔」。键名不支持占位符。

```json
{
  "orderId": "${uuid()}",
  "userId": "${userBase}${seq(1000, 1)}",
  "amount": "${float(1, 999, 2)}",
  "status": "${choice(pending|paid|shipped|closed)}",
  "region": "${region}",
  "createdAt": "${now(YYYY-MM-DDTHH:mm:ss[Z])}",
  "birthday": "${date(1970-01-01, 2005-12-31)}",
  "flag": "${bool()}",
  "items": { "$each": { "count": 3, "of": { "sku": "SKU${int(100,999)}", "i": "${index()}" } } }
}
```

函数集：`int(min,max)` `float(min,max,decimals)` `bool()` `string(len,charset?)` `uuid()` `choice(a|b|c)`（**即「随机从列表筛选」**）`seq(name?,start?,step?)` `now(pattern?,offsetMs?)` `date(from,to)` `timestamp(unit?)` `index()`，外加裸名 `${region}` 取具名变量。

具名变量与内联函数的差异（最易做错，写进文档注释）：**具名变量每条消息只解析一次**，多处引用同值（订单号在三个字段里必须一致）；**内联函数每次出现独立解析**；`$each` 每一项是独立作用域，`index()` 取该项序号。

落位：`src/shared/template-engine.ts`（词法/解析）+ `src/shared/template-resolver.ts`（纯函数 `resolveTemplate(body, variables, opts) → {json,bytes}|{error,path}`）。放 `src/shared/` 是硬要求：只有它同时在 `tsconfig.json`（renderer，strict）和 `tsconfig.node.json` 的 include 里；模块内禁止 import Node/Electron/dayjs（渲染层有 dayjs，主进程没有），日期格式化自带约 40 行。

**主进程解析实发**（连续模式时页签可能已切走，主进程必须自足），渲染层只为预览解析；同源 → 预览即所发，带 `seed` 时逐字节一致，用 xorshift32 替代 `Math.random` 保证可复现。既有 `messages:send` 与 TopicDetail 轻量发送面板**不动**。

闸门：解析后重新校验 `RESOLVED_MAX_BYTES = 5MB`（模板 ≤1MB，但 `$each` + 大 count 能撑爆；不做这步就是 `Buffer.from` OOM 而不是友好错误），按 `validateLimits` 风格抛中文说明（不走 zod——zod 失败只会回 `Invalid input parameters`）。

CodeMirror：依赖装 **devDependencies**（`electron-builder.json` 的 `files` 只有 `dist/**`+`package.json`，渲染层由 vite 打进 `dist/renderer`，react/antd/echarts 全在 devDeps——装错位置只是让安装包多带一份没人 require 的 node_modules）。不用 `@uiw/react-codemirror`：要的是三主题 × 四字号档的精确接线，包装层会挡路。`cmTheme.ts` 的颜色**一律引用 CSS 变量**（`var(--color-bg-base)` / `--color-border` / `--color-text-primary` / `--font-size-sm` / `--font-mono`），字号不写 px —— 这是 `[data-font-size]` 三档覆盖（`index.css:100-125`）能生效的唯一办法（`App.tsx:22-110` 的 antd token 喂不到 CM 里）。占位符高亮用纯装饰 `ViewPlugin`（不参与 parse，绝不影响 JSON 校验）；补全由 `.` 或 Ctrl+Space 触发（`$` 在 JSON 字符串里，别抢普通字符）。变量侧表用 antd `Form.List` 三列（名称/表达式/当前解析示例值），存**独立列** `variables_json` 而非塞进正文的 `$let` 头部（后者会把业务报文和元数据混在一段里，格式化后顺序漂移、复制时容易一起粘走）。

## 六、schema 校验、消息追踪（诚实边界）

- **broker schema**：`resources:getTopicSchema` 走 `registerClientHandler` 打 `GET /admin/v2/schemas/{tenant}/{ns}/{localName}`（分区主题用无索引名）。仓库里现在**没有任何 schema 调用**（`resource-api.ts` grep 无匹配），这台 standalone broker 上该路由是否挂载**未实测**，所以实现必须是：404/HTML404/异常 → `{available:false, reason}`，UI 显示「此集群未提供 schema 注册表」并自动退回本地校验，**不出红色错误横幅**。拿到 schema 后仅做 JSON 结构的浅校验（必填键、类型、枚举），Avro/Protobuf 明确标注不支持。
- **本地校验**（默认档）：从模板当前预览 JSON 推断结构（键集合 + 类型 + 数组首元素），逐条比对后续预览，报「缺 key / 类型变了」。零依赖、零网络，这是真正日常有用的那一半。
- **消息追踪**：broker 侧 `PulsarMessageTracer` 是 broker 配置、默认关闭，admin 也没有 trace 路由 → **做不了真 trace**。替代方案：发送时可选注入 `traceId` property，「追踪」= 用 Reader 按时间窗扫描 + 按 property/前缀过滤，叠加 topic `/stats` 的 producers/subscriptions/backlog 快照，拼成一条时间线；UI 文案叫「消息定位」而不是「消息追踪」，别给用户错误承诺。
- **`getMessagesById`**：admin 路由 404，只能靠已缓存的 `messageIdBytes` 在活 consumer 上 `seek`；界面只在「本会话收到过的消息」上提供该操作。

## 八、风险与对策

- **原生绑定段错误**：任何新轮询循环照抄 `hasNext()`+250ms，`readNext()` 不带参；会话收尾一律 `withHardTimeout`；producer close 前必 flush。
- **IPC 载荷体积**：5MB 单条上限不变；批推加 4MB 字节闸门；`messageIdBytes` 每条几十字节可接受。
- **主进程内存增长**：`MAX_PENDING_ACKS/BYTES` 双阈值 + `MAX_SESSIONS`；长驻 producer 只持一个 producer 对象。
- **页签风暴**：会话不进页签栏（§5）；`producer:listSessions` 用于界面恢复。
- **依赖体积**：CodeMirror 进 devDeps，`verify-package.mjs` 断言不回归；包体增量在批次 0 量一次。
- **UI 实机验证**（项目硬要求）：`scripts/cdp.mjs` 起 dev 实例逐屏截图；生产实例占单例锁，用**仓库外**的 `--user-data-dir`；主进程改动不热更新，必须重启；三主题 × 三字号档都要看编辑器与指标行；broker 192.168.222.121 上真发真收。
- **不做**：事务消息、KV 集群、SoLr、multi-topic schema、broker 侧 tracer 开关、任何 admin REST 发送/peek 尝试。
