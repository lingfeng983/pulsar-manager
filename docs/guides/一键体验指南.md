# 一键体验指南

不想先搭集群？项目根目录提供了 standalone Pulsar 的 docker-compose，5 分钟跑通全部功能。

## 前置条件

- 已安装 Docker（Windows 上建议 Docker Desktop）
- 不需要本地 Pulsar 环境，全部由容器提供

## 步骤

### 1. 启动 standalone Pulsar

在项目根目录执行：

```bash
docker compose up -d
```

- 首次会拉取镜像 `apachepulsar/pulsar:3.3.0`（约 1.5 GB，视网速等待几分钟）
- 启动后监听两个端口：`6650`（broker 消息端口）、`8080`（admin HTTP 端口）
- 查看启动日志确认就绪：

```bash
docker compose logs -f pulsar
```

看到类似 `messaging service is ready` 的输出即为就绪。若端口被占用，改 `docker-compose.yml` 里的宿主机端口映射后再启动。

> 想换 Pulsar 版本，改 `docker-compose.yml` 中的 `image` 标签即可（如 `apachepulsar/pulsar:3.0.0`、`4.1.0`）。

### 2. 启动应用

```bash
npm install
npm run dev
```

或直接使用分发仓下载的安装包。

### 3. 添加集群

在应用「集群管理」中新增集群：

| 字段 | 值 |
| --- | --- |
| 集群名称 | 随意（如 `demo`） |
| Admin 地址 | `http://127.0.0.1:8080` |
| Broker 地址 | `pulsar://127.0.0.1:6650` |
| 凭据 | 留空（standalone 默认无需凭据） |

点「测试连接」应提示成功，并读回 Pulsar 版本。

### 4. 开始体验

- **消息收发**：新建租户 → 命名空间 → Topic，用「消息浏览器」发一条消息、再消费回来
- **快速压测**：顶部导航「快速压测」对 Topic 并发写入，观察吞吐与延迟统计
- **监控与拓扑**：首页总览、集群拓扑直接有数据
- **集群巡检**：资源树集群右键或顶栏「巡检」，跑一次体检报告
- **策略管理 / 函数 / Schema / 权限**：standalone 上均可直接操作

### 5. 结束体验

```bash
docker compose down        # 停止并删除容器（保留数据卷，下次启动数据仍在）
docker compose down -v     # 连同数据卷一起删除，彻底清理
```

## 常见问题

- **端口被占用**：修改 `docker-compose.yml` 的 `ports` 映射（如 `"6651:6650"`、`"8081:8080"`），应用里对应填写新端口
- **内存不足**：调小 `PULSAR_MEM`（`-Xms256m -Xmx512m -XX:MaxDirectMemorySize=512m`）
- **连接失败**：确认容器已就绪（`docker compose ps` 状态为 Up）；Windows 上注意 127.0.0.1 是否被代理拦截，必要时用 `localhost`
